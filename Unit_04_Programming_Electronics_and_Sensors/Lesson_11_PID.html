PID Line Following

Unit 4 · Programming, Electronics & Sensors · Lesson 4.11

Lesson 4.11 · Weeks 22–23

Learning Objectives

By the end of this lesson you will be able to:

  • Compute a weighted sensor error from the 5-sensor IR array.
  • Implement proportional (P) control to steer L.E.O. on a line.
  • Add derivative (D) and integral (I) terms to reduce oscillation and steady-state error.

You Will Need

  • L.E.O. robot with OSOYOO 5-sensor IR array (wired from Activity 4.10)
  • Black-tape line course on a white surface
  • motor.py installed on Pico

You Will Produce

  • A compute_error() function using weighted sensor positions
  • A P-control loop that follows a line
  • A PD-control loop that reduces oscillation

Why Binary Control Isn't Enough

⚠️ Binary Control

  • Abrupt left/right switching — full speed turns only
  • Produces a zigzag path even on straight sections
  • Loses the line easily on sharp curves
  • Can't distinguish "slightly off" from "way off"

✅ PID Control

  • Correction is proportional to how far off-center
  • Small error → gentle correction; large error → strong correction
  • Handles straight sections, gentle curves, and sharp bends
  • One number (error) drives everything

The key idea: replace the if/elif tree with a single numeric error value — a measure of how far the detected line is from the center of the sensor array. Then use that number to calculate exactly how much to correct.

The 5-Sensor Array (Review)

From Lesson 4.10: 5 digital outputs, 0 = line detected (dark surface absorbs IR), 1 = no line. Assign a weight to each sensor position, with center = 0:

SensorGPIOWeightMeaning
S0GP6−2Far left
S1GP7−1Slightly left
S2GP80Center
S3GP9+1Slightly right
S4GP10+2Far right

⚠️ Inverted Logic!

0 means the sensor sees the line — the dark surface absorbs IR, so the sensor returns LOW. 1 means no line. This is backwards from what most people expect. Always verify with a print() before writing control logic.

Computing the Weighted Error

error = Σ(weight × detected) / Σ(detected)

Where detected = 1 − sensor_value (inverts the signal so 1 = line seen, 0 = no line).

  • For each sensor seeing the line, add its weight to the total.
  • Divide by the number of sensors that see the line — keeps the magnitude consistent regardless of how many sensors are on the tape.
  • Result: 0 when centered, negative when line is left, positive when line is right.
  • Returns None if no sensors see the line (robot is lost).
def compute_error(sensors): """Weighted position error. Returns float or None if line not found.""" weights = [-2, -1, 0, 1, 2] total_weight = 0 count = 0 for i in range(5): detected = 1 - sensors[i] # invert: 0→line present total_weight += weights[i] * detected count += detected if count == 0: return None # no sensors see the line return total_weight / count

Step 1 — Proportional (P) Control

correction = Kp × error

Motor speeds: left = base_speed + correction  ·  right = base_speed − correction

When the line is to the right (positive error), left motor speeds up and right slows — steering right. The response is always proportional to how far off-center the robot is.

import time import motor Kp = 25 # start here; tune by observation base_speed = 40 # % duty cycle while True: sensors = read_sensors() error = compute_error(sensors) if error is None: motor.drive(0, 0) # lost the line — stop continue correction = Kp * error left = base_speed + correction right = base_speed - correction motor.drive(left, right) time.sleep(0.01)

Tuning Kp

Too low → sluggish, misses curves. Too high → oscillates wildly. Start at Kp = 20–25 and adjust in steps of 5. Get P working before adding D or I.

Tuning Kp — What to Watch For

Too Low (Kp < 15)

  • Robot drifts slowly off the line
  • Falls off on any curve
  • Fix: Increase Kp by 5

Just Right

  • Smooth tracking on straight sections
  • Handles gentle curves cleanly
  • Small wobble on transitions — acceptable

Too High (Kp > 50)

  • Robot oscillates left-right rapidly
  • May lose the line entirely
  • Fix: Decrease Kp, or add D term

Suggested starting values based on speed:

base_speed (%)Starting Kp
3015 – 25

5035 – 45

Higher speed → robot has less time to react → needs higher Kp. Re-tune every time you change base_speed.

Step 2 — Add the D Term (Derivative)

The D term reacts to how fast the error is changing. It damps oscillation — if the robot is swinging toward center quickly, D reduces the correction before it overshoots.

correction = Kp × error + Kd × (error − prev_error)
Kp = 25 Kd = 10 # start at ~0.4 × Kp base_speed = 40 prev_error = 0 while True: sensors = read_sensors() error = compute_error(sensors) if error is None: motor.drive(0, 0) prev_error = 0 continue correction = Kp * error + Kd * (error - prev_error) prev_error = error # always update before next loop left = base_speed + correction right = base_speed - correction motor.drive(left, right) time.sleep(0.01)

Tuning Kd

Start with Kd ≈ 0.3–0.5 × Kp. Increase if oscillation persists; decrease if the robot responds sluggishly to curves. Always tune Kp first before adding Kd.

Step 3 — The I Term (Optional / Advanced)

The I term corrects persistent steady-state error — e.g., one motor is slightly weaker, so the robot always drifts right even when centered. It accumulates error over time to push back.

correction = Kp·error + Kd·(error − prev_error) + Ki·integral
Ki = 0.05 # keep very small! integral = 0 MAX_INTEGRAL = 30 # anti-windup clamp # inside the loop, before computing correction: integral += error integral = max(-MAX_INTEGRAL, min(MAX_INTEGRAL, integral)) correction = (Kp * error + Kd * (error - prev_error) + Ki * integral)

⚠️ Integral Windup

Without the MAX_INTEGRAL clamp, the integral grows without bound and causes massive overcorrection. Always clamp it.

⚠️ Most Robots Don't Need Ki

Start with P. Add D. Only add I if there is a persistent drift that D doesn't fix. An unnecessary I term usually makes things worse.

Debug Challenge

This PD controller has two bugs. Find and fix them before running on the robot.

Kp = 25 Kd = 10 prev_error = 0 while True: sensors = read_sensors() error = compute_error(sensors) correction = Kp * error + Kd * (error - prev_error) # BUG 1 left = base_speed + correction # BUG 2 right = base_speed - correction motor.drive(left, right) time.sleep(0.01)

What are the bugs?

  • Bug 1: prev_error is never updated after the correction is calculated. The D term always computes error − 0, so derivative control never works. Fix: add prev_error = error at the end of the loop.
  • Bug 2: base_speed is used but never defined. The robot will crash with a NameError. Fix: add base_speed = 40 before the loop.
