IR Sensing: Light vs. Dark

Each sensor has two components side by side: an IR LED that emits infrared light, and an IR detector (phototransistor) that measures how much comes back.

How It Works

Output Truth Table

SurfaceIR ReflectionPin OutputMeaning
Light (floor)High1 (HIGH)No line
Dark (tape)Low0 (LOW)Line detected
Key Rule: 0 = line detected  |  1 = no line
This is the opposite of what you might expect — keep it in mind when writing your logic!

Hardware Overview

The OSOYOO 5-channel IR line tracking sensor module puts five emitter/detector pairs in a single row. Each pair produces one digital output pin.

Module Features

  • 5 independent IR emitter/detector pairs
  • Digital output per sensor (0 or 1 — no analog needed)
  • Onboard indicator LEDs — each lights when that sensor detects the line
  • Trim potentiometer for sensitivity adjustment
  • Works at 3.3 V or 5 V (use 3.3 V on the Pico 2W)
The indicator LEDs are your best friend during setup. Before running any code, slide the module over the line by hand — watch the LEDs blink on and off to confirm the sensors are working.

Sensor Positions

S3 is center — the reference sensor. When the robot is on track, S3 should be over the line.

Wiring to the Pico 2W

Connect 7 wires total: VCC, GND, and one wire per sensor output (OUT1–OUT5).

Module Pin Pico 2W Pin Notes
VCC 3.3V (Pin 36) Use 3.3 V — the Pico's GPIO is not 5 V tolerant
GND GND (any GND pin) Share GND with the rest of the circuit
OUT1 (S1, leftmost) GP6 Adjust to match your wiring
OUT2 (S2) GP7
OUT3 (S3, center) GP8
OUT4 (S4) GP9
OUT5 (S5, rightmost) GP10
Pin Order Matters: Adjust the GPIO numbers to match your actual wiring. Whatever pins you use, S1 must map to the leftmost sensor and S5 to the rightmost — otherwise left/right steering will be reversed.
Double-check VCC: Some OSOYOO modules work at either 3.3 V or 5 V. On the Pico 2W, always use the 3.3 V pin (Pin 36) — do not connect to VBUS (5 V) or you risk damaging the GPIO pins.

Reading 5 Sensors at Once

A list comprehension lets us read all five pins in one line and store the results as a list.

import machine, time # Sensor pins — adjust to match your wiring (S1=left, S5=right) SENSOR_PINS = [6, 7, 8, 9, 10] sensors = [machine.Pin(p, machine.Pin.IN) for p in SENSOR_PINS] def read_sensors(): """Return list of 5 values: 0=line, 1=no line""" return [s.value() for s in sensors] # Test — run this to see live readings while True: vals = read_sensors() print(vals) # e.g. [1, 1, 0, 1, 1] = center on line time.sleep_ms(100)

Tip: Run the test loop first, before writing any driving code. Slide L.E.O. over the track by hand and watch the values in the serial monitor. This confirms your wiring is correct and the sensors are reading as expected.

Calibration Check

Before writing any driving logic, verify that your sensor readings make sense on your specific track.

  1. Place the robot on the white surface next to the line — all sensors should read [1, 1, 1, 1, 1]
  2. Slide the robot so only the center sensor (S3) is over the black line — should read [1, 1, 0, 1, 1]
  3. Check each sensor individually by sliding the module across the line — each sensor should flip from 1 to 0 as it crosses
  4. Adjust the trim pot on the module if readings are inconsistent or the sensors don't switch cleanly
  5. Use the onboard indicator LEDs for a quick visual check — no code needed
If you see [0, 0, 0, 0, 0] everywhere or readings don't change at all:
  • Check VCC — is it connected to 3.3 V?
  • Check GND is shared
  • Verify the module's indicator LEDs light at all
  • Confirm your GPIO pin numbers match the code
Trim Pot Tip: Turn the pot slowly with a small screwdriver. Clockwise usually increases sensitivity (sensors trigger more easily). Find the setting where sensors read 1 cleanly on white and 0 cleanly on the black tape — no flickering.

Steering Decisions

Binary line following works by matching the current sensor pattern to a known situation, then issuing a fixed motor command. It's a priority-based lookup — not an average or calculation.

Sensor Pattern Situation Action Motor Command
[1, 1, 0, 1, 1] Centered on line Go straight drive(40, 40)
[1, 0, ?, 1, 1] Slightly left of center Turn right gently drive(50, 20)
[0, ?, 1, 1, 1] Far left Turn right hard drive(60, 0)
[1, 1, ?, 0, 1] Slightly right of center Turn left gently drive(20, 50)
[1, 1, 1, ?, 0] Far right Turn left hard drive(0, 60)
[1, 1, 1, 1, 1] No line detected Slow search spin drive(20, -20)
Priority order matters: Check center first. If center is already on the line, don't bother checking the others. The if / elif chain handles this automatically — the first matching condition wins.

Putting It Together

import motor, time def follow_line_binary(): while True: v = read_sensors() # [s1, s2, s3, s4, s5], 0=line if v[2] == 0: # center on line → straight motor.drive(40, 40) elif v[1] == 0: # slightly left → turn right motor.drive(50, 20) elif v[0] == 0: # far left → hard right motor.drive(60, 0) elif v[3] == 0: # slightly right → turn left motor.drive(20, 50) elif v[4] == 0: # far right → hard left motor.drive( 0, 60) else: # no line at all → slow search motor.drive(20, -20) time.sleep_ms(10) follow_line_binary()
Start slow: Begin at speed 40. Once the robot is reliably tracking, increase speed gradually. Most line-follow failures at high speed are just too much momentum to steer.
Don't forget: This function uses read_sensors() — make sure that function and the sensors list are defined earlier in the same file before calling follow_line_binary().

Debug Challenge

This code should follow a line, but L.E.O. just spins in place constantly. Find the two bugs.

import machine, motor, time SENSOR_PINS = [6, 7, 8, 9, 10] sensors = [machine.Pin(p, machine.Pin.IN) for p in SENSOR_PINS] def read_sensors(): return [s.value() for s in sensors] def follow_line_binary(): while True: v = read_sensors() if v[2] == 1: # BUG 1: should be == 0 (1 = no line!) motor.drive(40, 40) elif v[1] == 0: motor.drive(50, 20) elif v[0] == 0: motor.drive(60, 0) elif v[3] == 0: motor.drive(20, 50) elif v[4] == 0: motor.drive( 0, 60) else: motor.drive(20, -20) time.sleep_ms(10) follow_line_binary # BUG 2: missing () — this is just a reference, not a function call
Bug 1 — Wrong comparison value
Line: if v[2] == 1:
Fix: if v[2] == 0:
Remember: 0 = line detected. Checking for 1 means "go straight when there is NO line at center" — the exact opposite of what we want, so the robot always falls to the else (spin) case.
Bug 2 — Function never called
Line: follow_line_binary
Fix: follow_line_binary()
Without parentheses this is just a reference to the function object — it doesn't run. Python doesn't raise an error; it silently does nothing. The robot never even starts.
