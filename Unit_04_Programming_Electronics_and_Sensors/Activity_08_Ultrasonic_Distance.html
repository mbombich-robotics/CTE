Ultrasonic Distance Sensing

Verify all three sensors, read distances, and understand what the numbers mean.

~25 min HS AER
1
Verify Setup
5 min

Before reading any distances, confirm that the mux and all three sensors are responding. Load the test script below in Thonny and run it.

sensor_check.py
from machine import I2C, Pin
import time
from leo import i2c, mux, sensor

# Scan the I2C bus — mux (0x77) and sensor (I2C address) should appear
devices = i2c.scan()
print("I2C devices found:", [hex(d) for d in devices])

# Test each mux channel — sensor should respond on channels 2, 3, 4
for ch in [2, 3, 4]:
    mux.select_channel(ch)
    d = sensor.distance_cm()
    if d is None:
        print(f"CH {ch}: no response — check wiring")
    else:
        print(f"CH {ch}: OK — {d:.1f} cm")
1
Open and run sensor_check.py

The Shell panel should print a device list and a reading for each channel. You expect to see at least two hex addresses (the mux and the sensor).

2
Check all three channels respond

Each channel should print "OK" with a distance. If one says "no response," check the sensor's connector on the mux board before continuing.

✓
Checkpoint 1

All three channels print "OK" with a distance reading. You may continue.

2
Read All Three Sensors
8 min

Now run a continuous read loop that prints all three sensors together. This is the pattern your robot programs will use.

read_all.py
from leo import mux, sensor
import time

while True:
    # LEFT sensor — mux channel 2
    mux.select_channel(2)
    left   = sensor.distance_cm()

    # CENTER sensor — mux channel 3
    mux.select_channel(3)
    center = sensor.distance_cm()

    # RIGHT sensor — mux channel 4
    mux.select_channel(4)
    right  = sensor.distance_cm()

    print(f"L: {left}  C: {center}  R: {right}")
    time.sleep_ms(200)
1
Run the loop and watch the Shell output

You should see three values updating about 5 times per second. Numbers will vary based on what's in front of each sensor.

2
Move your hand in front of each sensor

Slowly bring your hand toward the LEFT sensor — only the L value should drop. Repeat for CENTER and RIGHT. Verify each sensor reads independently.

3
Note the maximum reliable range

Point each sensor across the room and observe the maximum value before it returns None. Record this — you'll use it to set thresholds later.

✓
Checkpoint 2

Moving your hand in front of each sensor changes only that sensor's reading. All three are independent.

3
Interpret the Readings
7 min

Raw numbers are useful, but labeled output is easier to reason about. Modify the print statement to add context.

labeled_output.py
from leo import mux, sensor
import time

def fmt(d):
    """Format a reading: show cm or 'OPEN' if None."""
    return f"{d:.0f} cm" if d is not None else "OPEN"

while True:
    mux.select_channel(2)
    left   = sensor.distance_cm()
    mux.select_channel(3)
    center = sensor.distance_cm()
    mux.select_channel(4)
    right  = sensor.distance_cm()

    print(f"LEFT: {fmt(left):>8}  CENTER: {fmt(center):>8}  RIGHT: {fmt(right):>8}")
    time.sleep_ms(200)
💡
What does OPEN mean?

When the sensor returns None, no echo came back in time. That means either nothing is in range, or the sensor is pointed at something that absorbs sound (like thick foam). None = "I don't see anything" — not an error.

4
Add a None Guard
5 min

Using a None value in math causes a TypeError crash. Add a guard before any comparison or calculation.

none_guard.py
mux.select_channel(3)
center = sensor.distance_cm()

# Method 1: explicit check
if center is None:
    print("Center: nothing detected")
elif center < 30:
    print(f"CLOSE: {center:.1f} cm")
else:
    print(f"Clear: {center:.1f} cm")

# Method 2: or-substitution (compact)
center_safe = center or 999   # None becomes 999 (very far away)
if center_safe < 30:
    print("Close!")
TRY IT Trigger the None crash intentionally

Remove the guard and write if center < 30: directly. Point the sensor at the ceiling (nothing in range) and run it. You should see a TypeError. Then add the guard back and confirm the crash goes away.

✓
Checkpoint 3

Your labeled read loop runs without crashing even when a sensor returns None.

5
Reflect
5 min
Q1

Why must you call mux.select_channel() before each sensor.distance_cm()? What would happen if you skipped it?

Q2

The sensor returns None when nothing is in range. Why is it better to treat None as "far away" rather than as zero when making navigation decisions?

Q3

You noticed the loop takes about 200 ms per full scan (three sensors × ~60 ms each + delays). If L.E.O. drives at 20 cm/s, how far could it travel between scans? Is that a concern?
