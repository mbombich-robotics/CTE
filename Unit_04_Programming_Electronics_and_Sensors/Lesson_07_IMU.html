IMU Heading Hold

Unit 4 · Programming, Electronics & Sensors · Lesson 4.7

Lesson 4.7 · Weeks 17–18

Learning Objectives

By the end of this lesson you will be able to…

  • Explain how the MPU6050 gyroscope measures rotation rate in degrees per second
  • Read and integrate gyro Z output to track L.E.O.'s heading in real time
  • Write a heading-hold loop and a tank_turn(deg) function for precise turns

Why Motors Don't Drive Straight

No two motors are identical. Friction, battery voltage, and manufacturing tolerances make one side spin slightly faster — even at the same PWM duty cycle. The robot curves instead of going straight.

We need a sensor that tells us how much we've rotated, not just how fast the motors are spinning.

✗ Open Loop (no feedback)

  • Set left = right = 50
  • Robot curves slightly left or right
  • Error grows with distance traveled
  • No way to correct — code is blind

✓ Closed Loop (with IMU)

  • IMU detects any yaw rotation
  • Code compares heading to target (0°)
  • Slows one motor to correct the drift
  • Self-corrects every 20 ms

The GY-521 & MPU6050

GY-521 is the blue breakout board — it adds a voltage regulator and I2C pull-up resistors.
MPU6050 is the sensor chip soldered to it.

6-Axis Sensor

  • 3-axis gyroscope — measures rotation rate (°/s)
  • 3-axis accelerometer — measures g-force
  • We only need gyro Z (yaw) to steer L.E.O.
  • 16-bit ADC gives very fine resolution

Interface & Key Detail

  • I2C protocol, address 0x68
  • Connected through TCA9548A mux (0x70)
  • Select the mux channel before talking to IMU
  • Chip boots in sleep mode — must wake it

Reading Gyro Z

The MPU6050 stores measurements in hardware registers (one byte each). Gyro Z spans two consecutive bytes — read them together and combine into a signed 16-bit integer, then scale to degrees per second.

Key Registers

NameAddressPurpose
PWR_MGMT_10x6BSleep / wake control
GYRO_ZOUT_H0x47Gyro Z — high byte
GYRO_ZOUT_L0x48Gyro Z — low byte

Reading 0x47 with length 2 grabs both bytes in one call (big-endian order).

Scaling: raw → °/s

Raw value÷ 131.0Result
131÷ 131.01.0 °/s
655÷ 131.05.0 °/s
1310÷ 131.010.0 °/s
−1310÷ 131.0−10.0 °/s

Default range = ±250 °/s → 131 LSB per °/s.
Negative values = counter-clockwise rotation.

Step 1: Wake Up

The MPU6050 boots with its sleep bit set and ignores all requests. Write 0x00 to register 0x6B (PWR_MGMT_1) to clear the sleep bit and start the chip.

import machine, struct, time i2c = machine.I2C(0, scl=machine.Pin(1), sda=machine.Pin(0), freq=400000) # Select IMU channel on TCA9548A mux (your channel may differ) i2c.writeto(0x70, bytes([1 << 0])) IMU_ADDR = 0x68 # Wake up: clear sleep bit in PWR_MGMT_1 (register 0x6B) i2c.writeto_mem(IMU_ADDR, 0x6B, bytes([0x00])) time.sleep_ms(100) print("IMU ready")

Why the 100 ms delay?

The chip needs time to complete its internal startup after waking. Skipping the delay may cause the first few reads to return garbage values. 100 ms is conservative and safe.

Step 2: Read & Scale

Read 2 bytes starting at 0x47, unpack as a signed big-endian integer, then divide by 131.0 to get degrees per second.

def read_gyro_z(): """Return rotation rate in degrees/second (positive = clockwise).""" data = i2c.readfrom_mem(IMU_ADDR, 0x47, 2) # GYRO_ZOUT_H/L raw = struct.unpack('>h', data)[0] # signed 16-bit big-endian return raw / 131.0 # ±250°/s → 131 LSB/°/s # Quick test — run this loop to see the gyro live while True: print(f"Gyro Z: {read_gyro_z():.2f} °/s") time.sleep_ms(100)

Gyro Bias — Hold Still First

With L.E.O. at rest, any non-zero reading is gyro bias — a tiny built-in offset. It's normal and small (typically <2 °/s). It will cause yaw to drift slowly, but that error is negligible for short maneuvers.

Step 3: Track Heading

A gyroscope reports rotation rate (°/s), not angle. To get heading you integrate: multiply the rate by how much time has passed, then add it to the running total.

yaw = yaw + (°/s) × dt

where dt = loop interval in seconds (20 ms = 0.020 s)

LOOP_MS = 20 # run loop every 20 ms yaw = 0.0 # degrees from start, positive = clockwise start = time.ticks_ms() while True: gz = read_gyro_z() dt = LOOP_MS / 1000.0 # convert ms → seconds yaw += gz * dt # integrate: add rotation this tick print(f"Yaw: {yaw:+.1f}°") time.sleep_ms(LOOP_MS)

Drift Over Time

Gyro bias multiplies by elapsed time — after several minutes yaw will wander noticeably. For a 2-second straight run the drift is tiny and acceptable.

Driving Straight with IMU

Every loop tick: read gyro, update yaw, then compare to target (0°). If drift exceeds the dead band, nudge the faster motor down slightly. The dead band prevents over-correction when the error is tiny.

import motor DEAD_BAND = 2.5 # ignore drift smaller than this (degrees) def drive_straight_imu(speed=50, duration_ms=2000): """Drive forward for duration_ms using IMU to hold heading.""" yaw = 0.0 t0 = time.ticks_ms() while time.ticks_diff(time.ticks_ms(), t0) < duration_ms: gz = read_gyro_z() yaw += gz * (LOOP_MS / 1000.0) if yaw > DEAD_BAND: motor.drive(speed - 8, speed) # drifted right → slow left motor elif yaw < -DEAD_BAND: motor.drive(speed, speed - 8) # drifted left → slow right motor else: motor.drive(speed, speed) time.sleep_ms(LOOP_MS) motor.drive(0, 0)

Precise Turns: tank_turn()

Drive one side forward and the other backward — the robot spins in place. Integrate yaw each tick until the accumulated angle reaches the target, then stop and let the robot settle.

def tank_turn(degrees, speed=30): """ Turn in place by 'degrees'. Positive = clockwise (right), negative = counter-clockwise (left). """ target = abs(degrees) direction = 1 if degrees > 0 else -1 yaw = 0.0 while abs(yaw) < target - 2: # 2-degree stop margin gz = read_gyro_z() yaw += gz * (LOOP_MS / 1000.0) motor.drive(direction * speed, -direction * speed) time.sleep_ms(LOOP_MS) motor.drive(0, 0) time.sleep_ms(150) # settle before next move # Drive a square: 4 sides × 90° turns for _ in range(4): drive_straight_imu(speed=50, duration_ms=1500) tank_turn(90)

Debug Challenge

This code should drive straight for 2 seconds. Find and fix the two bugs.

import machine, struct, time, motor i2c = machine.I2C(0, scl=machine.Pin(1), sda=machine.Pin(0), freq=400000) i2c.writeto(0x70, bytes([1 << 0])) i2c.writeto_mem(0x68, 0x6B, bytes([0x00])) time.sleep_ms(100) def read_gyro_z(): data = i2c.readfrom_mem(0x68, 0x47, 2) raw = struct.unpack('>h', data)[0] return raw / 131.0 yaw = 0.0 LOOP_MS = 20 t0 = time.ticks_ms() while time.ticks_diff(time.ticks_ms(), t0) < 2000: gz = read_gyro_z() yaw += gz # BUG 1: missing × dt if yaw > 2.5: motor.drive(42, 50) elif yaw < -2.5: motor.drive(50, 42) else: motor.drive(50, 50) time.sleep_ms(LOOP_MS) motor.stop() # BUG 2: motor.stop() doesn't exist

What are the bugs?

  • Bug 1: yaw += gz — missing * (LOOP_MS / 1000.0). Without multiplying by dt, yaw accumulates raw °/s values instead of degrees, so the heading calculation is completely wrong.
  • Bug 2: motor.stop() — this function does not exist in motor.py. The correct call is motor.drive(0, 0).
