Activity 4.10 — Binary Line Following

Lesson 4.10  ·  L.E.O. Robot  ·  MicroPython on Raspberry Pi Pico 2W

🕐 ~55 minutes Lesson 4.10
1
Wire & Test the Sensor Array
~10 min

L.E.O. uses an OSOYOO 5-channel IR line tracking sensor to detect black lines on a white surface. Before writing any following logic, wire the sensor and confirm that the raw readings make sense.

1
Connect the OSOYOO sensor to L.E.O.

Wire the five signal outputs to the Pico 2W: OUT1 → GP6, OUT2 → GP7, OUT3 → GP8 (center), OUT4 → GP9, OUT5 → GP10. Connect VCC → 3.3V (or 5V if your module requires it) and GND → GND. Double-check — adjust the pin numbers below if your physical wiring is different.

2
Open Thonny and create line_test.py

Make sure Thonny is connected to the Pico 2W (bottom-right should show "MicroPython (Raspberry Pi Pico 2W)").

3
Paste and run the sensor test
line_test.py
import machine, time

SENSOR_PINS = [6, 7, 8, 9, 10]  # S1(left)…S5(right) — adjust if needed
sensors = [machine.Pin(p, machine.Pin.IN) for p in SENSOR_PINS]

def read_sensors():
    return [s.value() for s in sensors]

while True:
    print(read_sensors())
    time.sleep_ms(100)
4
Test over the white floor

Hold the sensor array over the white surface (no line). All five values should read 1 — the IR light reflects strongly back to the receiver.

5
Test over the black line

Slowly move the sensor over the black tape. At least one value should flip to 0 — the black surface absorbs IR light so the receiver sees less reflection.

⚠
All values stuck at 0 or all stuck at 1?

Check that VCC is connected to 3.3V or 5V (not GND), and verify your GPIO pin numbers match the actual wires. If everything looks right, try adjusting the trim potentiometer on the module.

☑
Checkpoint 1

You can see values changing in the Thonny console as you move the sensor over and off the line.

2
Calibrate & Understand the Output
~15 min

Before writing the following logic you need to understand exactly what patterns the sensors produce at each robot position. Run line_test.py while moving L.E.O. slowly across the line and observe each reading.

1
Center the robot over the line

Position L.E.O. so S3 (index 2, center sensor) is directly over the black tape. The console should show [1, 1, 0, 1, 1].

2
Shift slightly left

Nudge the robot left until S2 and S3 both cover the line. Expected output: [1, 0, 0, 1, 1]. Two sensors see the line simultaneously.

3
Move far left

Slide the robot further left so the line passes under S1. Expected: [0, 1, 1, 1, 1]. Only the leftmost sensor sees the line.

4
Watch the indicator LEDs

The OSOYOO module has five small LEDs — one per sensor — that light up when that sensor detects the line. Use these for quick visual checks while the robot is running and you cannot see the Thonny console.

5
Adjust the trim pot if needed

If readings are inconsistent (flipping on a solid surface, or not flipping over the line), use a small screwdriver to turn the trim potentiometer on the module. Clockwise typically increases sensitivity.

Sensor pattern reference

Robot Position Sensor Pattern Meaning
Centered [1, 1, 0, 1, 1] S3 on line
Slightly left [1, 0, 0, 1, 1] S2 + S3 on line
Far left [0, 0, 1, 1, 1] S1 + S2 on line
Slightly right [1, 1, 1, 0, 0] S4 + S5 on line
💡
0 means line detected — 1 means no line

This is the opposite of what you might expect. Black absorbs IR light, so the receiver sees very little signal — the digital output goes LOW (0). White reflects IR strongly, so the output stays HIGH (1). Keep this in mind when writing your if-statements: you are checking for == 0, not == 1.

☑
Checkpoint 2

You can predict what the sensor output will be before reading it — look at the robot's position, then check the console to confirm.

3
Binary Line Following
~25 min

Now you will write the control logic. The idea is simple: check which sensor (or sensors) sees the line and steer toward it. A chain of if/elif statements handles each case.

1
Create line_follow.py

Open a new file in Thonny. Copy your sensor setup from Part 1 — the SENSOR_PINS list, the sensors list comprehension, and the read_sensors() function — and paste it at the top of the new file.

2
Add the motor import and the following function
line_follow.py
import machine, time
import motor

SENSOR_PINS = [6, 7, 8, 9, 10]  # S1(left)…S5(right) — adjust if needed
sensors = [machine.Pin(p, machine.Pin.IN) for p in SENSOR_PINS]

def read_sensors():
    return [s.value() for s in sensors]

def follow_line_binary():
    """Follow a black line on a white surface using binary sensor logic."""
    while True:
        v = read_sensors()           # [s1, s2, s3, s4, s5], 0=line, 1=no line

        if   v[2] == 0:             # center on line → go straight
            motor.drive(40, 40)
        elif v[1] == 0:             # slightly left  → gentle right turn
            motor.drive(50, 20)
        elif v[0] == 0:             # far left       → hard right turn
            motor.drive(60,  0)
        elif v[3] == 0:             # slightly right → gentle left turn
            motor.drive(20, 50)
        elif v[4] == 0:             # far right      → hard left turn
            motor.drive( 0, 60)
        else:                       # no line seen   → slow search spin
            motor.drive(20, -20)

        time.sleep_ms(10)

follow_line_binary()
3
Place L.E.O. on the line course and run

Start the robot at the beginning of the course. Begin at speed 40 — resist the urge to go faster until you have confirmed it follows reliably. Press the red Stop button in Thonny (or the hardware button if wired) to halt the robot.

4
Diagnose direction problems

If the robot turns the wrong direction when it drifts off the line, your S1/S5 left-right orientation may be flipped. Check whether S1 is on the physical left or right side of the robot and swap the pin assignments if needed.

💡
Robot turns the wrong direction?

If the robot turns LEFT when it drifts right (and vice versa), swap your S1 and S5 pin assignments at the top of the file. The sensor may be mounted with S1 physically on the right side of the robot.

⚠
Keep speed low until it works

Do not increase motor.drive() values above 60 until the robot is reliably following the line. At high speed, the sensor reads the new position too late and the robot overshoots every correction.

★
Challenges
early finishers

Completed the checkpoint? Pick any challenge below — they are independent, so you can try them in any order.

C-1 Speed Test

Gradually increase your base motor speed: 40 → 50 → 60 → 70. Run a full lap at each speed and note whether the robot stays on the line. What is the fastest speed before it reliably loses the line on a curve? Record your findings.

C-2 Two-Sensor Center

Modify the code so that when both v[1] and v[2] are 0 simultaneously (S2 and S3 both see the line), the robot drives straight. Add this as a new elif branch before the single-sensor cases. Does this make following smoother on a wide line?

C-3 Speed Modulation

Use two different speeds: on a straight (only S3 sees the line) drive both motors at 60; on a curve (only S1 or S5 sees the line) reduce both to 30. Does the robot complete a lap faster than a fixed-speed version? Time a few laps and compare.

C-4 Figure-8

Set up (or find) a figure-8 track that crosses over itself. What happens when the robot reaches the intersection where two lines cross at right angles? Does it follow correctly, freeze, or go the wrong way? How could you modify the code to handle the intersection?

Reflection Questions

Answer these in your portfolio. Use complete sentences and refer to specific parts of the code or your test results where relevant.

Q1

The sensor outputs 1 when there is no line and 0 when it detects a line. Why does IR line sensing work this way? What physical property of white vs. black surfaces causes this difference in output?

Q2

Your robot follows a straight line perfectly but loses the line on sharp curves. What specific change (or changes) would you make to the code to help it handle tight turns without losing the line?

Q3

The else branch currently spins the robot in place (motor.drive(20, -20)) when no sensor sees the line. Describe what would happen if you replaced that with motor.drive(30, 30) — driving both motors forward. When is a spin better? When might driving forward be better?

Q4

Look at the priority order of the if/elif chain. If v[2] == 0 AND v[1] == 0 at the same time (both S3 and S2 see the line), which branch executes? Is this the correct behavior for that situation? Why or why not?
