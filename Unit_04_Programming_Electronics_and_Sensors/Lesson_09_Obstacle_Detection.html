The Threshold Decision

The simplest form of obstacle avoidance is a single rule: if distance drops below a threshold, stop.

# Threshold = stop distance (cm) STOP_DIST = 25 while True: mux.select_channel(3) center = sensor.distance_cm() if center is None or center > STOP_DIST: drive_forward() # safe else: stop() # obstacle!
None means nothing detected — that's safe, so treat it the same as a large distance.

Choosing a Threshold

  • Too small (5 cm): robot hits the wall before it has time to stop
  • Too large (60 cm): robot stops far away and never really navigates
  • 20–30 cm is a good starting point for classroom speeds
Momentum matters. A robot at full speed needs more stopping distance than one moving slowly. If you tune at high speed and then reduce it, you may need to re-tune.

Which Way to Turn?

When the center sensor says "stop," L.E.O. needs to decide which direction is more open. That's what the left and right sensors are for.

while True: # Read all three sensors mux.select_channel(2) left = sensor.distance_cm() or 999 mux.select_channel(3) center = sensor.distance_cm() or 999 mux.select_channel(4) right = sensor.distance_cm() or 999 if center > 25: drive_forward() elif left > right: turn_left() # more space on left else: turn_right() # more space on right

The or 999 Trick

None or 999 evaluates to 999 in Python. This converts a "no reading" into a very large distance — which means "nothing blocking." It's a compact way to handle the None case in comparisons.

Decision rule: Turn toward the sensor with the larger reading. Larger distance = more open space.

Proportional Correction

Simple on/off logic works, but it produces jerky motion. Proportional correction smooths things out by adjusting the response continuously based on how far off you are.

On/Off (Bang-Bang)

  • If too close → full left turn
  • If far enough → straight
  • Result: constant switching, robot weaves

Proportional

  • Error = target distance − actual distance
  • Correction = error × small gain value
  • Result: gentle steering that gets smoother as the robot reaches the target

Wall Following Example

Keep RIGHT sensor reading at a target of 20 cm:

TARGET = 20 # desired distance (cm) KP = 3.0 # gain — start small! error = right - TARGET correction = KP * error # Positive error → too far → steer right # Negative error → too close → steer left set_steering(correction)
Tune KP carefully. Too large and the robot oscillates. Too small and it barely responds. Start at 1.0 and work up.

What You'll Build

Activity 4.9 walks you through two levels of obstacle behavior, each building on the last:

Level 1 — Stop & Turn

  • Drive forward until center sensor triggers
  • Use left/right readings to pick a turn direction
  • Resume driving after clearing the obstacle
  • Goal: navigate around a single box

Level 2 — Wall Following

  • Choose a wall to follow (left or right sensor)
  • Set a target distance from the wall
  • Apply proportional correction to stay parallel
  • Goal: navigate a corridor without touching the walls
These same ideas scale up. Real self-driving vehicles, warehouse robots, and vacuum cleaners all use variations of obstacle thresholds and proportional corrections. The math gets more sophisticated — the concepts stay the same.
