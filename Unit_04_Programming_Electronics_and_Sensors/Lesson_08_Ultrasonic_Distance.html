How Ultrasonic Ranging Works

Ultrasonic sensors measure distance the same way a bat does — by sending out a sound pulse and timing how long the echo takes to come back.

The Math

Sound travels at about 343 m/s (0.0343 cm/μs) in air.

The pulse travels out and the echo travels back — so the distance is half the total travel time:

distance = echo_time × 0.0343 / 2
The I2C version handles all of this internally. You call sensor.distance_cm() and get back a number — no pulse timing in your code.

Why I2C?

A traditional HC-SR04 uses four wires per sensor: VCC, GND, TRIG, and ECHO. That works fine for one sensor — but L.E.O. has three.

GPIO Trigger/Echo

  • 4 wires per sensor
  • 3 sensors = 12 wires total (6 GPIO pins)
  • Your code must manually send the pulse, time the echo, and do the math
  • Sensors cannot share any pins

I2C Version

  • Only 2 signal wires: SDA and SCL
  • 3 sensors share the same two wires
  • Pulse timing and math done inside the sensor chip
  • You just ask: "how far?"
Trade-off: All three I2C sensors have the same fixed address. You can only talk to one at a time — which is why L.E.O. uses a mux chip to switch between them.

The I2C Mux

The TCA9548A is a switch chip between the Pico 2W and the three sensors. At any moment, only one sensor is connected to the bus.

How It Works in Code

To read a sensor, you first select the channel, then request the reading:

# Switch mux to LEFT sensor mux.select_channel(2) left_cm = sensor.distance_cm() # Switch to CENTER sensor mux.select_channel(3) center_cm = sensor.distance_cm()
The mux is transparent to the sensors — they all think they are the only device on the bus.

Three-Sensor Layout

L.E.O.'s sensors are mounted at −45°, 0°, and +45° relative to the robot's forward direction. Together they give a wide field of view.

SensorAngleMux ChannelDetects
LEFT−45°CH 2Obstacles to the left
CENTER0°CH 3Direct obstacles ahead
RIGHT+45°CH 4Obstacles to the right
Practical range: These sensors work reliably from about 5 cm to 300 cm. Readings beyond that may be unreliable. Very close objects (<5 cm) may return None.

Why These Angles?

  • Center catches anything straight ahead — the most critical direction for avoidance
  • ±45° gives early warning for obstacles approaching from the sides
  • Together they cover roughly 90° of detection arc in front of the robot
  • The robot's own body is behind the sensors — rear detection not needed for basic navigation

Reading the Sensors

The provided library handles all the setup. In your program, you only need these three steps for each sensor read:

from leo import mux, sensor import time while True: # LEFT sensor (ch 2) mux.select_channel(2) left = sensor.distance_cm() # CENTER sensor (ch 3) mux.select_channel(3) center = sensor.distance_cm() # RIGHT sensor (ch 4) mux.select_channel(4) right = sensor.distance_cm() print(f"L: {left:.1f} C: {center:.1f} R: {right:.1f}") time.sleep_ms(200)

What Each Line Does

  • select_channel(2) — switches mux to the LEFT sensor
  • distance_cm() — sends pulse, waits for echo, returns cm (or None if out of range)
  • sleep_ms(200) — wait 200 ms between full scans so sensors don't interfere
Always check for None. If a sensor gets no echo (nothing in range, or something too close), it returns None instead of a number. Using None in math will crash your program.

Handling None & Next Steps

A sensor returns None when no echo arrives in time — the object is either too far away or the sensor is uncovered. A simple guard keeps your program safe:

mux.select_channel(3) center = sensor.distance_cm() if center is None: print("CENTER: out of range") elif center < 30: print(f"WARNING — only {center:.1f} cm ahead!") else: print(f"Clear — {center:.1f} cm")
