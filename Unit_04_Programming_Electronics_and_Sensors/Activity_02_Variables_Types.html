Step 3 — The division surprise

Try these and record what comes back:

10 / 2 type(10 / 2) 10 // 2 type(10 // 2)
Python 3 rule: / always returns a float, even when both numbers are whole. // is floor division — it discards the decimal and returns an int. Most Python on computers uses /; most MicroPython hardware functions require int, which is why you'll see explicit int() conversions.
✓

Checkpoint — before moving on

Run type(10 / 2) and confirm it says <class 'float'>, not int. If you see <class 'int'>, double-check you used /, not //.

Part 2: Type Conversion

~10 minutes · REPL only

You convert a value's type by calling the type name as a function: int(), float(), str().

Step 1 — Basic conversions

int(3.9) # what do you expect? int(3.1) # same direction? int(-2.8) # what about negative? float(5) # int → float str(42) # number → text int("7") # text → number
int() truncates, it does NOT round. int(3.9) → 3, not 4. The decimal is simply cut off. Positive or negative, it always moves toward zero.

Step 2 — Trace the set_speed() calculation

Work through the set_speed() math step by step. Run each line and write down what you get:

pct = 50 # Step A — what does division give you? pct / 100 # Step B — multiply by 65535 pct / 100 * 65535 # Step C — what type is the result? type(pct / 100 * 65535) # Step D — convert to int int(pct / 100 * 65535)

Now repeat with pct = 25 and pct = 100. Do you notice a pattern in the final int value?

What you're looking at: at 100% speed, duty = 65535; at 50%, duty = 32767; at 25%, duty = 16383. The library handles this math so students just pass a percentage — clean interface, ugly math hidden inside.

Step 3 — Type mismatch error

See what happens when types don't agree:

"speed: " + 50

Python raises a TypeError. Fix it by converting 50 to a string first:

"speed: " + str(50)
✓

Checkpoint

Confirm that int(50 / 100 * 65535) gives you 32767. If it's off, check your parentheses — Python evaluates / and * left to right, so the order matters.

Part 3: Clamp & Conventions

~15 minutes · REPL + motor.py open in Thonny

Step 1 — max() and min() in the REPL

Run each line. Before you press Enter, predict the output.

max(3, 7) min(3, 7) max(0, -10) min(100, 150) abs(-42) abs(42) max(1, 5, 3, 2) # more than two args

Step 2 — Build the clamp step by step

The clamp pattern keeps a value inside a range. Let's build it with value = 120 (over the limit) and the range 0–100.

value = 120 # Step A — cap at 100 with min() min(100, value) # Step B — now floor at 0 with max() max(0, min(100, value)) # Step C — try with value = -10 (under the limit) value = -10 max(0, min(100, value))
Reading the nesting: Python evaluates the innermost call first. min(100, value) runs first — it caps the value at 100. Then max(0, result) runs on the capped result — it floors it at 0. No matter what value is, the final output is always between 0 and 100.

Step 3 — Write the full set_speed expression

Combine the clamp with the percentage-to-duty conversion. pct is what the student passes in (could be anything).

pct = 150 # student passed 150 — out of range int(max(0, min(100, pct)) / 100 * 65535) # what do you get? what would happen without the clamp?
