Variables

A variable is a name that holds a value. You create one with an assignment statement — the name on the left, the value on the right.

speed = 100 message = "go" running = True temp = 98.6

You can reassign a variable at any time — the old value is replaced:

speed = 100 speed = 50 # now 50, not 100 speed = speed + 10 # now 60

Naming rules

  • Start with a letter or underscore — never a digit
  • Letters, digits, and underscores only — no spaces or dashes
  • Case-sensitive: speed and Speed are different variables
  • Avoid Python keywords: for, if, True, etc.

Good names vs bad names

✓ drive_time = 1.5 ✓ turn_count = 0 ✗ 2nd_motor # starts with digit ✗ drive time # space not allowed ✗ x # too vague

Use type() to inspect any value or variable:

>>> type(5) <class 'int'> >>> type(3.14) <class 'float'> >>> type("go") <class 'str'> >>> speed = 100 >>> type(speed) <class 'int'>

Why does type matter?

MicroPython functions are strict about types. duty_u16() expects an int. If you pass a float, it raises a TypeError. Division in Python always returns a float — so 50 / 100 gives 0.5, not 0. Knowing the type tells you when a conversion is needed.

Type Conversion

You convert between types by calling the type name as a function: int(), float(), str().

>>> 50 / 100 0.5 # division → float >>> int(0.5) 0 # truncates (cuts off) >>> int(3.9) 3 # NOT rounded — truncated >>> float(5) 5.0 >>> str(42) '42' # now text, not a number

The motor.py problem

In set_speed(), we calculate:

pct / 100 * 65535

Even if pct is an int, dividing by 100 produces a float. So the whole expression is a float. duty_u16() needs an int — that's why we wrap it:

int(pct / 100 * 65535)

The int() truncates the decimal. At these scale factors the rounding error is less than 1 — small enough not to matter.

Built-in Functions: max(), min(), abs()

These three are built into Python — no import needed. They show up constantly in robotics code.

max()

Returns the largest of its arguments.

max(3, 7) # 7 max(0, -5) # 0 max(1,5,3,2) # 5

min()

Returns the smallest of its arguments.

min(3, 7) # 3 min(100, 150) # 100 min(1,5,3,2) # 1

abs()

Returns the absolute value (strips the sign).

abs(-5) # 5 abs(5) # 5 abs(-0.3) # 0.3

Combining them — the clamp

You can nest function calls. The inner call runs first, then the outer call uses its result.

# clamp value to 0–100: max(0, min(100, value)) # step by step: # 1. min(100, value) → caps at 100 # 2. max(0, result) → floors at 0

Why the clamp matters

In set_speed(), if a student passes 150, the raw math gives a duty cycle above 65535 — which crashes MicroPython with a ValueError. The clamp silently corrects it to 100 before the conversion:

int(max(0, min(100, pct)) / 100 * 65535)

Naming Conventions

Python doesn't enforce access control — you can technically reach any name from anywhere. Instead, programmers use naming conventions as a communication system: a way of saying "here's how this is intended to be used."

StyleMeaningExample from motor.pyRule
plain_name Public — part of the interface students use forward(), set_speed(), stop() Use freely
_underscore Private — internal detail, don't call directly _speed, _drive(), _L_INA Leave alone
ALL_CAPS Constant — value set once, never changed FULL = 65535 Read, don't reassign

Public vs private — a car analogy

The steering wheel, pedals, and gear shift are the public interface — designed for you to use. The steering rack, fuel injectors, and ABS pump are the private internals — they work behind the scenes. You don't reach through the dashboard to grab the rack directly. Same idea with _drive(): it works, but forward() is the right handle.

Python doesn't stop you

motor._drive(1,0,1,0) works. Python won't throw an error. But you bypass the speed setting, and you've coupled your code to an internal detail that might change. The convention is a promise between programmers, not a lock.

When you see an underscore, the message is: "I didn't design this for you to call — use the public API instead."
