The Problem: Copy-Paste Code

You built SOS in Activity 5.1. Here's what the S alone looks like written the "long way":

# S — three short blinks led.value(1); time.sleep(0.1) led.value(0); time.sleep(0.1) led.value(1); time.sleep(0.1) led.value(0); time.sleep(0.1) led.value(1); time.sleep(0.1) led.value(0); time.sleep(0.1) time.sleep(0.3) # letter gap

Full SOS = S + O + S = nine letters' worth of this. That's 40+ lines for 3 letters.

Why this breaks

  • Want to change 0.1 to 0.15? Update it in every single line
  • Miss one → silent bug: your dots are mixed timing
  • Hard to read — no labels, just numbers
  • Adding "SOS" for a second robot? Copy 40 lines again

The rule: DRY

Don't Repeat Yourself.

If you find yourself writing the same code more than once, that code belongs in a function — a named block you write once and call as many times as you need.

Anatomy of a Function

Every function starts with the same structure. Learn to read and write this pattern — you'll use it constantly.

def blink(duration_ms): led.value(1) time.sleep_ms(duration_ms) led.value(0) time.sleep_ms(100)

What each part means

  • def — keyword that starts every function; short for "define"
  • blink — the name you invent; use something descriptive
  • duration_ms — a parameter: a placeholder variable, filled in each time you call the function
  • Colon : — required after the closing parenthesis
  • Indented body — every line inside the function must be indented 4 spaces or 1 Tab

Common mistakes

  • Forgetting the colon → SyntaxError immediately
  • Forgetting to indent the body → SyntaxError on the first body line
  • Misspelling the name when calling it → NameError: name 'blnk' is not defined
  • Calling the function before defining it → NameError

Calling a Function

Defining a function does nothing by itself — the body only runs when you call it. To call, write the name followed by parentheses and pass in the argument.

Same function, different behavior

The value you pass in becomes duration_ms inside the function. Change the argument, change the result — same four lines of code every time.

blink(100) # short — 100 ms on blink(400) # long — 400 ms on blink(50) # very short blink

Want to change the off-gap between blinks? Edit the 100 inside the function definition once — every call automatically uses the new value.

Three rules for calling

  • Always define the function before calling it — MicroPython reads top to bottom
  • Always include the parentheses, even with no arguments: dot() not dot
  • def is just a definition — the body runs only when called

Argument vs. parameter

Parameter — the name in the definition: duration_ms
Argument — the value you pass when calling: 100

Same concept, different moment. Parameter = placeholder. Argument = actual value.

Functions Calling Functions

Once you have blink(), you can build more specific functions on top of it — no raw numbers anywhere.

Build up in layers

def blink(duration_ms): led.value(1) time.sleep_ms(duration_ms) led.value(0) time.sleep_ms(100) def dot(): blink(100) # short blink def dash(): blink(400) # long blink def sos(): dot(); dot(); dot() # S time.sleep_ms(300) dash(); dash(); dash() # O time.sleep_ms(300) dot(); dot(); dot() # S time.sleep_ms(1000) while True: sos()

Compare: before vs. after

Without functions: 40+ lines, every timing value written out, nothing labeled.

With functions: sos() reads like English. Change timing in one place. Add a new Morse letter by writing one function.

Call order matters

MicroPython reads your file top to bottom. blink() must be defined before dot() calls it. dot() must be defined before sos() calls it.

Convention: put while True: at the very bottom — all your functions go above it.

Variable Scope

Every variable in Python exists in a scope — the region of code where it's visible. Functions introduce a second scope on top of the file's top-level scope.

Local scope

A variable created inside a function is local — it's born when the function is called and discarded when it returns. Code outside the function can't see it at all.

def blink(duration_ms): count = 0 # local led.value(1) ... # Outside: count doesn't exist print(count) # NameError!

Module-level scope

A variable created at the top of the file (not inside any function) is module-level. Every function in the file can read it — but writing to it requires a special keyword.

_speed = 0 # module-level def get_speed(): return _speed # reading: fine ✓ def set_speed(pct): _speed = pct # writing: creates a # NEW local _speed ✗

The trap

If you assign to a variable inside a function — anywhere in the function — Python treats it as local for the entire function. Even if a module-level variable has the same name, they are two different things. Writing to the local one has no effect on the module-level one.

The global Keyword

To write to a module-level variable from inside a function, declare it with global at the top of the function. This tells Python: "don't create a local; reach out to the module-level one."

Without global — broken

_speed = 0 def set_speed(pct): _speed = pct # new local _speed # module-level unchanged set_speed(50) print(_speed) # still prints: 0

_speed at the module level never changes. The local copy is thrown away the moment set_speed() returns.

With global — correct

_speed = 0 def set_speed(pct): global _speed # use module-level _speed = pct # now it sticks set_speed(50) print(_speed) # prints: 50 ✓

global _speed tells Python: this name refers to the module-level _speed, not a new local one.

Rule of thumb

Only use global when a function needs to write to a module-level variable that other parts of the program need to read later. In motor.py, set_speed() updates _speed so that get_speed() can retrieve the current value.

Putting It Together: set_speed()

The real motor.py combines everything from L5.2 (types, clamp) and L5.3 (functions, global) into one 6-line function.

Annotated motor.py

_speed = 0 # module-level state def set_speed(pct): global _speed # ① reach module-level pct = int(pct) # ② type safety pct = max(0, min(100, pct)) # ③ clamp _speed = pct # ④ store for get_speed() duty = pct * 655 # ⑤ scale 0–100 → 0–65500 pwm.duty_u16(duty) # ⑥ write to hardware def get_speed(): return _speed # reads module-level

Why each line is there

  • ① global — without this, _speed = pct would create a local that disappears on return
  • ② int() — converts 50.7 → 50 so the math stays clean
  • ③ clamp — enforces the contract: 0 ≤ speed ≤ 100, no matter what the caller passes
  • ④ _speed — stored so other functions (and the caller) can read the current value later
  • ⑤ 655 — maps 0–100 to 0–65500 (hardware range is 0–65535)

Call it like this

set_speed(75) # 75% power set_speed(0) # stop set_speed(150) # clamped to 100 set_speed(-10) # clamped to 0 print(get_speed()) # 0 (last clamped)
