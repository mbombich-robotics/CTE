What Is Digital Input?

So far you've used the Pico as an output device — your program tells the LED what to do. Digital input reverses that flow: the physical world sends information to the Pico.

Digital means only two possible states:

HIGH
3.3 V · value() = 1
LOW
0 V · value() = 0

Digital inputs on your robot

  • Mechanical switches (SW_2, SW_3 on the board)
  • IR line sensors — line or no line
  • Ultrasonic echo — pulse timing
  • Limit switches — hit a wall or not

When you call .value() with no argument on an input pin, it returns the voltage it's currently reading — 0 or 1.

Pull Resistors — Why They Matter

If you configure a pin as input but leave it unconnected, it "floats" — it picks up electrical noise from the airEE and reads unpredictably. You need to give it a defined default voltage.

For the EE-curious — what's actually happening

"From the air" implies antenna / RF pickup, which requires a half-wavelength conductor to be efficient. A 2 cm PCB trace has negligible radiation resistance at 50–60 Hz or even at AM radio frequencies. The real mechanisms are board-level.

The CMOS input buffer in its linear region. A floating CMOS input has essentially infinite DC impedance and roughly 5 pF of input capacitance. With no DC path to either rail, the pin voltage drifts toward Vdd/2 (≈1.65 V on a 3.3 V system) — right at the CMOS threshold, where buffer gain is highest. Millivolt disturbances are amplified to full logic swings.

Where the noise actually comes from:
• Capacitive crosstalk — the floating trace couples to adjacent PCB traces carrying switching signals. A few pF of coupling capacitance delivers enough charge to trip the threshold.
• Power supply ripple — Vdd is never perfectly flat; even a few mV of ripple shifts the threshold relative to the floating pin.
• The human body effect — bringing your hand near the board couples 50/60 Hz ambient electric field (from building wiring) onto the trace through body capacitance (~100–300 pF). This is the closest thing to "from the air" that's real — but it requires your body as the intermediary antenna.

"Reads unpredictably" actually understates it. A floating pin often latches to one state and stays there rather than randomly toggling. The behavior is deterministic for a given board in a given electromagnetic environment — but that environment changes when you route a nearby trace differently, add a cable, or put the board in a metal enclosure. The pin can read HIGH reliably in your lab for weeks, then read LOW consistently once shipped in a steel box. Worse than random: it passes your bench tests.

The pull resistor fixes all of this by providing a defined DC operating point firmly outside the buffer's linear region. The pin sits at 0 V (PULL_DOWN) or 3.3 V (PULL_UP) and can only be overridden by a deliberate, low-impedance switch closure.

Your interface board

SW_2 (GP12) and SW_3 (GP16) use PULL_DOWN. No external wiring needed — press the switch and value() returns 1.

Reading a Switch in Code

Three arguments to Pin() for an input: pin number, direction, pull resistor.

from machine import Pin # SW_2 is at GP12, uses PULL_DOWN sw = Pin(12, Pin.IN, Pin.PULL_DOWN) led = Pin("LED", Pin.OUT) while True: if sw.value() == 1: # pressed led.value(1) # LED on else: led.value(0) # LED off

Hold SW_2 → LED on. Release → LED off. The loop checks the switch hundreds of times per second.

What each part does

  • Pin.IN — configures the pin to read voltage, not drive it
  • Pin.PULL_DOWN — sets the default to LOW (0) so the pin never floats
  • .value() — returns 1 (HIGH) or 0 (LOW), no argument needed
  • == 1 — checks for the pressed state

If you used PULL_UP instead

The logic flips — pressed gives 0, not 1. You'd write if sw.value() == 0: to detect a press. Same hardware behavior, opposite numbers.
