Activity 5.5 — Drive Your L.E.O. Robot

Work through each part in order. Raise your hand at each checkpoint before moving on.

~35 minutes Lesson 5.5
1
Save motor.py to the Pico
~10 min

The motor.py file is a helper module — it sets up the motor pins once so every program you write can import motor and call clean functions. It lives on the Pico itself, not on your computer.

1
Open Thonny and connect your Pico

Confirm the status bar shows MicroPython (Raspberry Pi Pico) and a COM port.

2
Open a new file (Ctrl + N) and paste the code below

Use the copy button — do not retype this one. Pin numbers must match the interface board exactly.

motor.py — paste exactly
from machine import Pin, PWM

# ── Left motor (Motor A) ──────────────────────────────
_L_INA = Pin(2, Pin.OUT)
_L_INB = Pin(3, Pin.OUT)
_L_PWM = PWM(Pin(4)); _L_PWM.freq(20000)

# ── Right motor (Motor B) ─────────────────────────────
_R_INA = Pin(5, Pin.OUT)
_R_INB = Pin(6, Pin.OUT)
_R_PWM = PWM(Pin(7)); _R_PWM.freq(20000)

FULL = 65535
_speed = FULL           # current default — change with set_speed()

def set_speed(val):
    global _speed
    _speed = val

def _drive(la, lb, ra, rb):
    _L_PWM.duty_u16(_speed); _R_PWM.duty_u16(_speed)
    _L_INA.value(la);       _L_INB.value(lb)
    _R_INA.value(ra);       _R_INB.value(rb)

def forward():  _drive(1, 0, 1, 0)
def backward(): _drive(0, 1, 0, 1)
def left():     _drive(0, 1, 1, 0)
def right():    _drive(1, 0, 0, 1)
def stop():
    _L_PWM.duty_u16(0); _R_PWM.duty_u16(0)
    _L_INA.value(0);    _L_INB.value(0)
    _R_INA.value(0);    _R_INB.value(0)
3
Save to the Pico as motor.py

Press Ctrl + S. When the dialog asks where to save, click Raspberry Pi Pico. Name the file exactly motor.py (lowercase, no spaces). Click OK.

💡
Why does motor.py live on the Pico?

The Pico has its own flash storage. When you import motor in a program, MicroPython looks for motor.py on the Pico's file system — not on your computer. Saving it there once means every future program can use it without repeating all the pin setup code.

🔍
Motor going the wrong direction?

If forward() makes the robot go backward, or left() turns right, one of your motors is wired in reverse. Tell the teacher — this is a wiring fix, not a code fix. The interface board has a connector orientation that determines which direction is "forward." Don't try to fix it by swapping the INA/INB logic in motor.py unless the teacher instructs you to.

3
Drive a Square
~15 min

Now write a program that drives the robot through a square path: forward → turn right → forward → turn right → … four times. The robot uses time to decide when to stop — so your turn time determines how close to 90° each corner is. You'll need to tune it.

1
Open a new file (Ctrl + N) in Thonny's editor

You'll save this as square.py — separate from motor.py.

2
Type this starting program

The constants at the top are where you'll tune. Change only those two numbers — not the rest of the program.

square.py — starting point
import motor
import time

DRIVE_TIME = 1.5    # seconds driving straight
TURN_TIME  = 0.5    # seconds turning — adjust until corner = 90°

for _ in range(4):
    motor.forward()
    time.sleep(DRIVE_TIME)
    motor.stop()
    time.sleep(0.1)    # brief pause at corner
    motor.right()
    time.sleep(TURN_TIME)
    motor.stop()
    time.sleep(0.1)

💡
Robot drifts on straight sections?

Most real robots drift because one motor is slightly faster than the other. That's normal — precision driving without sensors requires tuning. You can compensate by passing a slightly lower speed to the faster motor: motor._drive(1,0,1,0, 65535, 60000) if you modify _drive() to accept separate left/right speeds. For now, just note the drift and move on.

Challenges
finish early?

Start from your working square.py. Each challenge takes 5–10 minutes.

C1 Figure-8

Drive a figure-8: square using right() turns, then square using left() turns. The second square runs counterclockwise. Hint: the turn time is the same — only the direction changes.

C2 Slow-Motion Square

Drive the same square at half speed. Add motor.set_speed(32767) at the top of your program, before the loop. Does the turn time need to change at half speed? Run it and find out.

C3 Pentagon

Change the loop from 4 to 5 sides and find the turn time for a 72° corner (360° ÷ 5 = 72°). How does this compare to the 90° turn time? Does the ratio make sense?

C4 Spiral (hard)

Drive a spiral by increasing DRIVE_TIME by 0.3 seconds each loop iteration. Hint: instead of a fixed DRIVE_TIME, use a variable that grows inside the loop.

loop hint
drive_t = 0.5
for _ in range(8):
    motor.forward()
    time.sleep(drive_t)
    motor.stop()
    motor.right()
    time.sleep(TURN_TIME)
    motor.stop()
    drive_t += 0.3      # each side is longer
